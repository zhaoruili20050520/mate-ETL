# ETL-Agent 页面操作流程指南

> 本指南基于 Web 控制台 UI（`http://localhost:8000`），按页面导航顺序描述每一步操作。
> 无需 curl 命令，全部通过浏览器完成。

---

## 前置准备

### 启动服务

开 3 个终端窗口分别运行：

```bash
# 终端 1：启动 Docker 基础设施
cd E:/xuexi/ETL-Agent/ETL-Agent
docker compose up -d

# 终端 2：启动 FastAPI 控制面（含前端页面）
uv run uvicorn etl_agent.main:app --host 0.0.0.0 --port 8000 --reload

# 终端 3：启动 Celery Worker + Beat（任务执行与定时调度）
uv run celery -A etl_agent.workers.celery_app worker -l info
uv run celery -A etl_agent.workers.celery_app beat -l info
```

等待约 60 秒，然后浏览器打开 `http://localhost:8000`，会看到登录页。

## 流程一：登录与总览

**页面路径**：登录页 → 总览

### 步骤 1.1 — 登录

1. 打开 `http://localhost:8000`
2. 登录页右侧表单：
   - **用户名**：输入 `admin`
   - **密码**：输入 `admin123`
   - 页面底部有提示："本地开发默认账号 admin / admin123"
3. 点击 **登录** 按钮

**验证**：登录成功后自动跳转到「总览」页面，左上角显示用户名和角色，右上角状态指示灯显示"全部服务正常"（绿色）。

### 步骤 1.2 — 查看总览

总览页面展示 5 个统计卡片：

| 卡片 | 含义 |
|------|------|
| 租户 | 当前租户数量（初始为 1） |
| 项目 | 已创建的项目数 |
| 数据连接 | 已配置的数据源连接数 |
| 管道 | 已生成的 ETL 管道数 |
| 执行记录 | 历史执行总数 |

下方有「发布链路」流程图，展示从需求到发布的 8 个阶段：需求解析 → 元数据 → 规划生成 → HOCON → 质量门禁 → 审批 → 执行 → 原子发布。

右下角「依赖服务」面板显示 PostgreSQL、Redis、SeaTunnel 三项服务的运行状态。

**验证**：三盏灯全绿表示环境就绪，可以开始后续操作。

## 流程二：项目管理

**页面路径**：侧边栏 → 工作台 → 项目

### 步骤 2.1 — 新建项目

1. 点击侧边栏 **项目**
2. 点击右上角 **新建项目** 按钮，展开输入面板
3. 填写：
   - **项目名称**：例如 `订单同步`
   - **说明**：例如 `将 MySQL 订单数据全量同步到 Doris`
4. 点击 **保存** 按钮

**验证**：页面弹出绿色提示"创建成功"，项目卡片出现在列表中，卡片上显示连接数、管道数、执行数（均为 0）。

## 流程三：数据连接配置

**页面路径**：侧边栏 → 工作台 → 连接

### 步骤 3.1 — 新增 MySQL 源连接

1. 点击侧边栏 **连接**
2. 点击右上角 **新增连接** 按钮，展开表单
3. 填写字段：

   | 字段 | 填写值 |
   |------|--------|
   | 所属项目 | 选择上一步创建的项目 |
   | 连接名称 | `订单MySQL` |
   | 数据库类型 | 选择 `MySQL` |
   | 主机地址 | `127.0.0.1` |
   | 端口 | `3307` |
   | 数据库名 | `testdb` |
   | 用户名 | `testuser` |
   | 密码 | `testpass` |

4. 点击 **保存连接** 按钮

**验证**：绿色提示"保存成功"，连接列表新增一行，显示连接名称、类型徽章（MySQL 紫色）、地址 `127.0.0.1:3307`。

### 步骤 3.2 — 新增 Doris 目标连接

重复上述步骤，创建 Doris 连接：

| 字段 | 填写值 |
|------|--------|
| 所属项目 | 同一个项目 |
| 连接名称 | `目标Doris` |
| 数据库类型 | 选择 `Doris` |
| 主机地址 | `127.0.0.1` |
| 端口 | `9030` |
| 数据库名 | `testdb` |
| 用户名 | `root` |
| 密码 | （留空或按实际填写） |

**验证**：连接列表中可见 2 条连接记录，分别标记为 MySQL 和 Doris。

## 流程四：管道生成与管理

**页面路径**：侧边栏 → 工作台 → 管道

> **注意**：当前版本的管道生成需要通过 API 调用自然语言生成接口，前端管道页面用于查看生成结果。
>
> 如果需要在前端完成完整端到端流程，请按以下步骤操作：

### 步骤 4.1 — 生成管道（通过 API 参考页）

1. 点击侧边栏底部 **API 参考** 链接，打开 API 文档页面
2. 找到 `POST /api/v1/pipelines/generate` 端点
3. 调用该端点，请求体示例：

   ```json
   {
     "project_id": "<你的项目ID>",
     "source_connection_id": "<MySQL连接ID>",
     "target_connection_id": "<Doris连接ID>",
     "natural_language": "将 test_users 表从 MySQL 全量同步到 Doris",
     "sync_mode": "full",
     "source_table": "test_users",
     "target_table": "test_users",
     "primary_keys": ["id"]
   }
   ```

4. 生成成功后，管道状态为 `validated`（已校验）或 `frozen`（已冻结）

### 步骤 4.2 — 查看管道列表

1. 回到控制台，点击侧边栏 **管道**
2. 表格显示所有管道，包含：
   - **管道**：名称
   - **状态**：徽章颜色——绿色"已校验"、紫色"已冻结"、黄色"草稿"、红色"异常"
   - **所属项目**
   - **更新时间**

**验证**：刚生成的管道出现在列表中，状态为"已校验"或"已冻结"。

## 流程五：执行记录监控

**页面路径**：侧边栏 → 工作台 → 执行记录

### 步骤 5.1 — 查看执行列表

1. 点击侧边栏 **执行记录**
2. 表格显示所有执行记录，列包括：

   | 列 | 说明 |
   |----|------|
   | 执行 ID | 缩略的 UUID |
   | 状态 | 徽章颜色对应不同状态（见下表） |
   | 所属项目 | 项目名称 |
   | 开始时间 | 执行启动时间 |
   | 完成时间 | 执行结束时间 |
   | SeaTunnel | SeaTunnel 作业 ID |

   **状态徽章对照**：

   | 状态 | 颜色 | 标签 |
   |------|------|------|
   | pending | 黄色 | 等待提交 |
   | running | 蓝色 | 运行中 |
   | quality_checking | 紫色 | 质量检查 |
   | publishing | 紫色 | 发布中 |
   | succeeded | 绿色 | 成功 |
   | failed | 红色 | 失败 |
   | rolled_back | 黄色 | 已回滚 |

### 步骤 5.2 — 总览页快捷查看

在总览页的「最近执行」面板也能看到最近 6 条执行记录的摘要。

**验证**：提交执行后，刷新执行记录页面，能看到对应记录从 `running` → `quality_checking` → `publishing` → `succeeded` 的状态流转。

## 流程六：知识库 — 文档管理

**页面路径**：侧边栏 → 知识库 → 文档管理

### 步骤 6.1 — 载入示例文档（快捷方式）

1. 点击侧边栏 **文档管理**
2. 点击右上角 **载入示例** 按钮
3. 系统自动导入预置的示例文档并完成分块和发布

**验证**：绿色提示"示例已载入"，文档列表显示多篇文档，状态为"已发布"（绿色徽章）。

### 步骤 6.2 — 手动导入文档

1. 点击右上角 **导入文档** 按钮，展开导入面板
2. 填写：

   | 字段 | 说明 |
   |------|------|
   | 文档标题 | 例如 `数据治理规范` |
   | 限制部门（可选） | 例如 `数据中心`，限制只有该部门可见 |
   | 文档内容 | 粘贴文档正文，系统自动分块 |
   | 分类标签 | 例如 `数据治理` |

3. 点击 **导入并分块** 按钮

**验证**：绿色提示"导入成功"，文档出现在列表中，初始状态为"草稿"（黄色徽章），分块数列显示切分的块数。

### 步骤 6.3 — 发布文档

1. 在文档列表中，找到状态为"草稿"的文档
2. 点击该行的 **发布** 按钮

**验证**：绿色提示"发布成功"，该文档状态变为"已发布"（绿色徽章），此后在问答工作台中可检索到。

### 步骤 6.4 — 删除文档

1. 点击文档行的 **删除** 按钮
2. 在确认弹窗中点击确定

**验证**：文档及其所有分块从列表中移除。

## 流程七：知识库 — 问答工作台

**页面路径**：侧边栏 → 知识库 → 问答工作台

### 步骤 7.1 — 提问

1. 点击侧边栏 **问答工作台**
2. 页面分为左右两栏：
   - **左侧**：聊天对话框，底部有输入框和"提问"按钮
   - **右侧**：检索详情面板（提问后显示命中分块和审计信息）
3. 在底部输入框输入问题，例如 `数据治理的核心原则是什么？`
4. 按 **Enter** 键或点击 **提问** 按钮

**验证**：
- 左侧对话框显示用户消息，随后显示"检索中..."加载动画
- 检索完成后，显示 AI 回答
- 回答下方可能附带徽章：蓝色"FAQ命中"（如果命中已发布 FAQ）、黄色"已记录缺口"（如果知识库无法回答）
- 右侧「检索详情」面板显示：
  - **允许访问的 Chunk**：绿色徽章列出命中的分块 ID
  - **被权限拦截**：红色徽章列出因权限不足被拦截的分块
  - **元数据**：FAQ 命中、缺口记录、延迟、会话 ID

### 步骤 7.2 — 连续提问

可连续提问多个问题，聊天记录按顺序显示在左侧对话框中。如果知识库无法回答某问题，会自动创建一条缺口记录。

## 流程八：知识库 — FAQ 管理

**页面路径**：侧边栏 → 知识库 → FAQ 管理

### 步骤 8.1 — 生成候选 FAQ

1. 点击侧边栏 **FAQ 管理**
2. 页面分为左右两栏：
   - **左侧**：候选 FAQ 列表
   - **右侧**：已发布 FAQ 列表
3. 点击候选面板右上角的 **生成候选** 按钮
4. 系统对最近 30 天的问答记录进行聚类分析

**验证**：
- 如果有相同或相似问题被多次提问，会生成候选 FAQ
- 候选列表显示：问题、频率（出现次数）、置信度（百分比徽章：≥80% 绿色、≥50% 黄色、<50% 红色）
- 如果没有达到聚类条件，提示"暂未达到聚类条件，请先积累相同提问"

### 步骤 8.2 — 审核候选 FAQ

每条候选 FAQ 有三个操作按钮：

| 按钮 | 操作 |
|------|------|
| **发布** | 将该候选 FAQ 发布为正式 FAQ，此后问答时优先命中 |
| **拒绝** | 标记为拒绝，不再出现在候选列表中 |
| **删除** | 彻底删除该候选记录 |

1. 审阅候选 FAQ 的问题和推荐回答
2. 点击 **发布** 或 **拒绝**

**验证**：发布后，该 FAQ 从候选列表移到右侧"已发布 FAQ"列表。

### 步骤 8.3 — 管理已发布 FAQ

已发布 FAQ 列表显示问题和回答摘要（前 80 字），每条可点击 **删除** 按钮移除。

## 流程九：知识库 — 缺口清单

**页面路径**：侧边栏 → 知识库 → 缺口清单

### 步骤 9.1 — 查看缺口

1. 点击侧边栏 **缺口清单**
2. 表格显示所有无法回答的问题：

   | 列 | 说明 |
   |----|------|
   | 问题 | 用户提过但知识库无法回答的问题 |
   | 部门 | 提问者所属部门 |
   | 频率 | 该问题被提问的次数 |
   | 最高相似度 | 与已有文档的最高相似度百分比 |
   | 状态 | 黄色"待处理"、蓝色"处理中"、绿色"已解决" |

### 步骤 9.2 — 筛选缺口

1. 点击表格上方的状态下拉框
2. 可选择：全部状态 / 待处理 / 处理中 / 已解决

### 步骤 9.3 — 标记缺口为已解决

1. 找到状态为"待处理"或"处理中"的缺口
2. 点击该行的 **标记解决** 按钮

**验证**：该缺口状态变为"已解决"（绿色徽章），"标记解决"按钮消失。

### 步骤 9.4 — 删除缺口

点击缺口行的 **删除** 按钮，确认后删除该记录。

## 全流程串联：端到端操作路线

将上述流程串联，可以完成一条完整的端到端验证链路：

```
流程一（登录）
  → 流程二（新建项目）
    → 流程三（配置 MySQL + Doris 两条连接）
      → 流程四（生成管道）
        → 流程五（查看执行记录，观察状态流转）
          → 流程六（导入知识库文档并发布）
            → 流程七（在问答工作台提问）
              → 流程八（生成 FAQ 候选并发布）
                → 流程九（查看缺口清单，标记解决）
                  → 流程十（运营看板确认指标）
```

| 阶段 | 覆盖流程 | 预计耗时 |
|------|---------|---------|
| ETL 链路 | 一→二→三→四→五 | 15-20 分钟 |
| 知识库闭环 | 六→七→八→九→十 | 10-15 分钟 |
| 全流程串联 | 一→十 | 25-35 分钟 |

## 常见问题排查

| 现象 | 原因 | 解决 |
|------|------|------|
| 登录提示错误 | 服务未启动或数据库未迁移 | 检查终端 1/2/3 是否运行，执行 `alembic upgrade head` |
| 总览页状态灯异常 | 某容器未就绪 | 在「系统状态」页查看详情，等待 Docker 容器健康 |
| 连接保存失败 | 表单字段不完整 | 检查所有必填项（名称、地址、端口、库名、用户名、密码） |
| 管道列表为空 | 未通过 API 生成 | 在「API 参考」页调用 `POST /pipelines/generate` |
| 执行记录一直 running | Celery Worker 未启动 | 检查终端 3 是否运行 Worker |
| 问答返回空回答 | 文档未发布 | 在「文档管理」页点击"发布"按钮 |
| FAQ 生成无候选 | 相似问题不足 | 先在问答工作台多次提问相同问题 |
| 运营看板数据为 0 | 尚无问答记录 | 先完成流程六和七，再刷新看板 |
