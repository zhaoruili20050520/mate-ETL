# ETL-Agent 全功能测试操作指南

> 本指南将完整功能测试拆为 **5 个独立操作流程**，每个流程可单独验证，也可串联为端到端演示。
> 所有操作通过 curl 命令行完成，也可用前端 UI（`http://localhost:8000/`）替代。

---

## 前置条件：环境启动

### 1. 启动 Docker 基础设施

```bash
cd E:/xuexi/ETL-Agent/ETL-Agent
docker compose up -d
```

等待所有容器健康（约 60-90 秒）：

```bash
docker compose ps
```

确认以下容器全部 `healthy`：

| 容器 | 端口 | 用途 |
|------|------|------|
| etl-agent-postgres | 15432 | 状态数据库 |
| etl-agent-redis | 6380 | Celery broker |
| etl-agent-vault | 8200 | 凭据加密存储 |
| etl-agent-mysql | 3307 | 源数据源 |
| etl-agent-doris-fe | 8030/9030 | 目标数仓 |
| etl-agent-doris-be | 8040/9050 | Doris 后端 |
| etl-agent-seatunnel | 5801 | 数据搬运引擎 |

### 2. 安装依赖 + 数据库迁移

```bash
cd E:/xuexi/ETL-Agent/ETL-Agent
uv sync                                    # 或: pip install -e ".[dev]"
uv run alembic upgrade head                # 或: alembic upgrade head
```

### 3. 启动应用服务

开 3 个终端窗口分别运行：

```bash
# 终端 1: FastAPI 控制面
uv run uvicorn etl_agent.main:app --host 0.0.0.0 --port 8000 --reload

# 终端 2: Celery Worker（执行任务）
uv run celery -A etl_agent.workers.celery_app worker -l info

# 终端 3: Celery Beat（定时调度）
uv run celery -A etl_agent.workers.celery_app beat -l info
```

### 4. 初始化种子用户

```bash
uv run python -m etl_agent.cli
```

这会创建默认管理员：`admin / admin123`，租户 `default`。

### 5. 验证服务健康

```bash
curl http://localhost:8000/health
```

期望返回 `"status": "ok"`，三项检查全绿。

## 流程一：用户体系与多租户初始化

**目标**：注册多用户、创建项目、分配角色，为后续四眼审批做准备。

### 步骤 1.1 — 登录 admin 用户

```bash
curl -s -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "admin123"}' | python -m json.tool
```

保存返回的 `access_token`：

```bash
export ADMIN_TOKEN="<上面返回的 access_token>"
```

### 步骤 1.2 — 查看当前用户上下文

```bash
curl -s http://localhost:8000/api/v1/auth/me \
  -H "Authorization: Bearer $ADMIN_TOKEN" | python -m json.tool
```

确认 `role` 为 `tenant_admin`，`tenant_id` 有值。

### 步骤 1.3 — 注册第二个用户（审批人）

```bash
curl -s -X POST http://localhost:8000/api/v1/auth/register \
  -H "Content-Type: application/json" \

```

curl -s -X POST http://localhost:8000/api/v1/tenants/default/members \
  -H "Authorization: Bearer $ADMIN_TOKEN" \

## 流程三：自然语言生成 → 冻结 → 四眼审批 → Commit

**目标**：走完从自然语言到 ExecutionRun 创建的完整治理链路。

### 步骤 3.1 — 自然语言生成 Pipeline

```bash
curl -s -X POST http://localhost:8000/api/v1/pipelines/generate \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": "<project_id>",
    "source_connection_id": "<source_connection_id>",
    "target_connection_id": "<target_connection_id>",
    "natural_language": "全量同步 test_users 表从 MySQL 到 Doris",
    "sync_mode": "full",
    "source_table": "test_users",
    "target_table": "test_users",
    "primary_keys": ["id"]
  }' | python -m json.tool
```

**检查返回**：
- `status` 应为 `validated`（或 `needs_clarification`，如果 LLM 需要补充参数）
- `etl_plan` 非空，含 source/target/mappings/sync_strategy
- `hocon_config` 非空，包含 `source`、`sink`、`Jdbc` 等关键词
- `validation_issues` 无 error 级问题

保存 `pipeline_id`。

如果返回 `needs_clarification`，补充回答：

```bash
curl -s -X POST http://localhost:8000/api/v1/pipelines/<pipeline_id>/clarify \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"answers": {"sync_mode": "full", "source_table": "test_users", "target_table": "test_users"}}' | python -m json.tool
```

### 步骤 3.2 — 冻结 Pipeline 版本

```bash
curl -s -X POST http://localhost:8000/api/v1/pipelines/<pipeline_id>/versions \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}' | python -m json.tool
```

期望返回 `version_number`、`sha256` 摘要、`status: frozen`。保存 `version_id`（即 `id` 字段）。

### 步骤 3.3 — 创建 Preparation 准备单

```bash
curl -s -X POST http://localhost:8000/api/v1/preparations \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "pipeline_version_id": "<version_id>",
    "data_classification": "internal",
    "is_production_source": false,
    "is_multi_tenant": false
  }' | python -m json.tool
```

检查返回的 `risk_level`（P0-P3）、`input_fingerprint`、`rollback_plan`。保存 `preparation_id`。

### 步骤 3.4 — 四眼审批

admin 作为数据审批人提交 approval：

```bash
curl -s -X POST http://localhost:8000/api/v1/preparations/<preparation_id>/approvals \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "approval_role": "data_checker",
    "decision": "approved",
    "comment": "字段映射和脱敏规则确认无误"
  }' | python -m json.tool
```

checker 作为安全审批人提交 approval：

```bash
curl -s -X POST http://localhost:8000/api/v1/preparations/<preparation_id>/approvals \
  -H "Authorization: Bearer $CHECKER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "approval_role": "security_checker",
    "decision": "approved",
    "comment": "资源范围和回滚方案确认安全"
  }' | python -m json.tool
```

查看审批列表：

```bash
curl -s "http://localhost:8000/api/v1/preparations/<preparation_id>/approvals" \
  -H "Authorization: Bearer $ADMIN_TOKEN" | python -m json.tool
```

**注意**：admin 是准备人，不能同时持有两个审批角色——这是四眼分离约束。两个角色必须由不同用户提交。

### 步骤 3.5 — Commit 签发 Capability

```bash
curl -s -X POST http://localhost:8000/api/v1/preparations/<preparation_id>/commit \
  -H "Authorization: Bearer $ADMIN_TOKEN" | python -m json.tool
```

期望返回 `status: committed`、`capability_id` 非空。保存 `execution_run_id`（即 `id` 字段）。

**验收点**：Preparation 经过 `prepared → approved → committed` 三个状态，Outbox 消息已写入。

## 流程四：SeaTunnel 执行 → 监督 → 质量发布

**目标**：Worker 自动消费 Outbox 消息，提交 SeaTunnel 作业，监督轮询，质量校验后原子 Swap 到正式表。

### 步骤 4.1 — 等待 Worker 自动消费

Outbox Publisher 每 5 秒轮询，execution_worker 会自动：
1. 消费 Capability
2. 从 Vault 物化凭据
3. 注入 HOCON
4. 提交 SeaTunnel 作业
5. 创建监督契约

观察 Celery Worker 终端日志，应看到 `ExecutionRun` 状态变为 `running`。

### 步骤 4.2 — 查看运行状态

```bash
curl -s "http://localhost:8000/api/v1/execution-runs/<execution_run_id>" \
  -H "Authorization: Bearer $ADMIN_TOKEN" | python -m json.tool
```

关注 `status` 字段变化：`pending → running → quality_checking → publishing → succeeded`。

### 步骤 4.3 — 查看执行指标

```bash
curl -s "http://localhost:8000/api/v1/execution-runs/<execution_run_id>/metrics" \
  -H "Authorization: Bearer $ADMIN_TOKEN" | python -m json.tool
```

返回指标时间序列（read_rows、written_rows、error_rows、bytes 等）。

### 步骤 4.4 — 查看执行事件日志

```bash
curl -s "http://localhost:8000/api/v1/execution-runs/<execution_run_id>/events" \
  -H "Authorization: Bearer $ADMIN_TOKEN" | python -m json.tool
```

应包含 `job_submitted`、`job_running`、`job_finished`、`quality_checking`、`job_published` 等事件。

### 步骤 4.5 — 查看质量报告

```bash
curl -s "http://localhost:8000/api/v1/execution-runs/<execution_run_id>/quality-report" \
  -H "Authorization: Bearer $ADMIN_TOKEN" | python -m json.tool
```

检查 `error_rate` ≤ `max_error_ratio`，`status: passed`。

### 步骤 4.6 — 查看发布尝试

```bash
curl -s "http://localhost:8000/api/v1/execution-runs/<execution_run_id>/publish-attempt" \
  -H "Authorization: Bearer $ADMIN_TOKEN" | python -m json.tool
```

确认 `strategy`（如 `doris_replace`）、`shadow_table`、`status: succeeded`。

### 步骤 4.7 — 验证 Doris 正式表数据

```bash
docker exec etl-agent-doris-fe mysql -h 127.0.0.1 -P 9030 -uroot -e "SELECT * FROM testdb.test_users LIMIT 5;"
```

期望看到 2 行数据（alice 和 bob），与 MySQL 源表一致。

### 步骤 4.8（可选）— 测试取消运行

如果作业仍在 running，可测试取消：

```bash
curl -s -X POST "http://localhost:8000/api/v1/execution-runs/<execution_run_id>/cancel" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"reason": "手动测试取消"}' | python -m json.tool
```

### 步骤 4.9（可选）— 测试回滚

如果作业已 succeeded（Swap 已完成），可测试回滚恢复：

```bash
curl -s -X POST "http://localhost:8000/api/v1/execution-runs/<execution_run_id>/rollback" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"reason": "手动测试回滚"}' | python -m json.tool
```

**验收点**：完整链路 `pending → running → quality_checking → publishing → succeeded` 走通，Doris 正式表有数据。

## 常见问题排查

| 现象 | 原因 | 解决 |
|------|------|------|
| `/health` 返回 503 | 某容器未就绪 | `docker compose ps` 检查，等待健康 |
| 生成 Pipeline 报 LLM 错误 | `.env` 中 `MODEL_API_KEY` 未配 | 填入有效 API Key |
| Worker 不消费消息 | Celery Worker/Beat 未启动 | 检查终端 2/3 是否运行 |
| SeaTunnel 作业失败 | Doris BE 未加入集群 | `docker logs etl-agent-doris-be` 检查 |
| 审批报 403 | 准备人自批 | 用另一个用户的 Token 提交第二个审批 |
| 知识库问答返回空 | 文档未 publish | 先 `POST /documents/{id}/publish` |
