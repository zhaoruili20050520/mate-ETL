# ETL-Agent

ETL-Agent 是一个面向数据管道生成、审批、执行、质量校验与知识库管理的平台。

主要能力：

- 通过自然语言生成 ETL 管道方案。
- 管理数据源连接、元数据探查、Pipeline 版本和审批流程。
- 执行质量校验、影子表核对、原子 Swap、正式发布与受管回滚。
- 提供知识文档导入、自动分块、四维权限、RAG 问答、FAQ 沉淀和缺口诊断。
- 使用 Redis 缓存已发布 FAQ，结合本地大模型生成知识库回答。
- 提供运营看板、审计记录、Token 消耗和响应时间趋势。

## 快速启动

```bash
cp .env.example .env
docker compose up -d
uv pip install -e ".[dev]"
make migrate
make run
```

启动后打开：

- 控制台：`http://127.0.0.1:8000/`
- 操作手册与 API 参考：`http://127.0.0.1:8000/manual`
- 健康检查：`http://127.0.0.1:8000/health`

本地依赖通常会运行在：

| 服务 | 地址 |
| --- | --- |
| PostgreSQL | `localhost:15432` |
| Redis | `localhost:6380` |
| SeaTunnel | `localhost:5801` |
| Vault | `http://localhost:8200` |
| MySQL | `localhost:3307` |

## 默认账号

| 账号 | 密码 | 作用 |
| --- | --- | --- |
| `admin` | `admin123` | 租户管理员，可以维护部门和角色权限 |
| `data_engineer` | `Maker@2026Etl` | 默认知识管理员 |
| `data_checker` | `Checker1@2026Etl` | 默认知识管理员 |
| `security_checker` | `Checker2@2026Etl` | 默认系统管理员 |
| `system_operator` | `Operator@2026Etl` | 默认系统管理员 |
| `auditor` | `Auditor@2026Etl` | 默认系统管理员 |

默认账号仅用于本地开发环境，不应直接用于生产环境。

### 账号与登录令牌有效期

- 账号密码**永不过期**，也没有修改密码接口，需要换密码时直接更新 `users.password_hash`。
- 登录令牌由 `JWT_EXPIRE_MINUTES` 控制。本地 `.env` 设为 `0`，表示**永不过期**：签发的 JWT 不带 `exp`，关闭浏览器后再次打开仍然是登录态（令牌存在 `localStorage`）。
- `JWT_EXPIRE_MINUTES` 设为正数（例如 `480`）即恢复限时令牌；生产环境请使用正数，并配合 HTTPS。
- 令牌签发后服务端不做吊销。需要让所有已签发的令牌立刻失效时，替换 `.env` 里的 `JWT_SECRET_KEY` 并重启服务，所有浏览器都需要重新登录。

## 知识库端到端演示：财务部制度隔离

本流程演示公开知识和受限知识如何按部门隔离，并验证 FAQ 缓存不会绕过权限控制。

### 1. 准备部门和用户

1. 使用 `admin / admin123` 登录控制台。
2. 打开“组织与权限”。
3. 创建两个部门：`财务部`、`市场部`。
4. 将 `data_engineer` 设置为“普通用户 / 提问者”，部门选择 `市场部`。
5. 将 `data_checker` 设置为“普通用户 / 提问者”，部门选择 `财务部`。
6. 打开“操作按钮权限”，配置“普通用户 / 提问者”，勾选“查看文档”和“知识问答”。

### 2. 准备知识文档

1. 进入“文档管理”。
2. 如果没有示例数据，点击“载入示例”。
3. 找到《差旅报销标准》，点击“分块编辑”，确认访问范围为“全局公开”，保存。
4. 找到《高管薪酬与股权激励细则》，点击“分块编辑”。
5. 将访问范围设置为“受限”。
6. 允许部门填写 `财务部`。
7. 允许角色可保留 `system_admin`。
8. 保存后确认文档状态为“已发布”。

如果只限制某个用户，可以在“允许用户 ID”中填写对应用户 UUID。如果填写了部门、角色或用户，访问范围会自动使用受限模式。

### 3. 验证公开文档

1. 打开一个独立浏览器标签页，使用 `data_engineer / Maker@2026Etl` 登录。
2. 进入“问答工作台”。
3. 提问：`差旅报销标准是多少？`
4. 应正常返回差旅住宿、交通和餐饮补贴相关信息。

### 4. 验证权限隔离

1. 继续使用 `data_engineer` 提问：`高管薪酬与股权激励细则是什么？`
2. 由于该用户属于“市场部”，系统应提示：

   `检测到相关制度文档，但您当前所属部门/角色无权查阅该内容。`

3. 另开标签页，使用 `data_checker / Checker1@2026Etl` 登录。
4. 提问同一个问题，应正常返回薪酬制度内容。

### 5. 沉淀 FAQ 并验证 Redis 缓存

1. 使用 `data_checker` 连续提问至少两次，问题文字和标点保持一致：

   `高管薪酬与股权激励细则是什么？`

2. 使用 `admin` 进入“FAQ 管理”。
3. 点击“生成候选”。
4. 找到对应问题并点击“发布”。
5. 使用 `data_checker` 再次提问，回答旁应显示“FAQ命中 · Redis缓存”。
6. 使用 `data_engineer` 再次提问，仍应显示权限缺失提示。

这表示 FAQ 缓存只加速回答，不会绕过部门、角色、个人和全局四维权限校验。

### 6. 验证知识缺口和运营看板

1. 使用任一普通用户提问一个知识库中不存在的问题，例如：

   `火星基地量子服务器故障怎么处理？`

2. 系统应提示没有找到相关内容，并自动记录知识缺口。
3. 使用 `admin` 打开“缺口清单”，可以查看问题、部门、频次、最高相似度和处理状态。
4. 打开“运营看板”，可以查看访问次数、独立人数、知识单元数、常见问题榜、知识热度榜、Token 消耗和响应时间趋势。

## 文档导入格式

单篇文档可以直接在“导入文档”面板中填写标题、分类、访问范围、部门和正文。

批量导入时，每篇文档使用单独一行 `---` 分隔：

```text
差旅报销标准
分类：财务制度
访问范围：public
正文内容写在下面

---
高管薪酬与股权激励细则
分类：人事制度
访问范围：restricted
部门：财务部,人力资源部
角色：system_admin
用户：用户UUID，逗号分隔
正文内容写在下面
```

导入后的文档默认为草稿状态，必须点击“发布”后才会参与问答检索。

## 权限模型

知识单元支持四维权限：

- 全局：所有登录用户都可以访问。
- 租户：当前租户内可以访问。
- 部门：用户所属部门在允许列表中。
- 角色：用户的角色在允许列表中。
- 个人：用户 UUID 在允许列表中。

部门、角色和个人属于并列授权条件，满足任意一项即可访问。
